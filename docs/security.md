# Security boundaries

Project YAML is root-owned and must not be group/other writable. It can authorize commands, hooks, artifact origins, service names, shared destinations and trust anchors. Never let application runtime identities or build sources edit it. Managed application parents cannot have symlink ancestors; current may only be a symlink to a direct managed release. Legacy real directories are preserved and require explicit migration.

`scdeploy-build` executes build commands, never root. Its worker environment excludes source tokens and manager credentials. `scdeploy` owns state, artifacts and selected application roots; exact sudoers lines authorize only start/stop/restart of configured units. Service preflight rejects root runtime users and units not using the configured current path. The manager is never run as root for build/deploy/rollback/recover. Administrative installation/provisioning is a separate reviewed operation.

Profiles reside under `/etc/scdeploy/secrets/PROFILE.json`, or the directory selected through systemd CREDENTIALS_DIRECTORY. Secret profiles must be regular files, mode 0600, owned by the manager identity (or root if the process has a permitted read mechanism). The containing directory is 0700. Install files using `install -o scdeploy -g scdeploy -m 0600`. Source profiles use `{"token":"NEW_INSTALLATION_TOKEN"}`. Store newly issued credentials only; revoke exposed legacy credentials. No real values are distributed in examples.

Public keys belong under a root-owned `/etc/scdeploy/trust`, outside writable workspaces/releases. Key rotation is an administrative change; retain old keys for verification/rollback of old releases or re-sign retained artifacts under a reviewed procedure. GitHub App issuance/rotation is external; short-lived installation tokens are supported as profile values.

All artifact transfers and notifications verify TLS. Downloads restrict origins and reject credentials in URLs, downgrade redirects and unsupported ports. Authorization is stripped across hosts. Signed manifests authenticate downloaded artifact provenance. The primary local Git pipeline instead pins the source SHA, completes an isolated build and records the full manifest and archive digest in the manager-owned SQLite audit; only this successful build ID enables local artifact installation without a signature. Retained releases are matched to their recorded manifests on rollback. The build user cannot write that ledger or artifact store. File hashes authenticate each payload file; a checksum downloaded beside a malicious artifact is insufficient. No shell=True is used; commands are argv arrays with deadlines and cancellation. Technical output is bounded and redacted; audit contains structured safe metadata rather than full confidential process output.

Manual approval is an explicit invocation of the source update pipeline or a selected artifact, recorded with its digest and actor. Automated approval is an administrator-owned policy, not an interactive approval ticket. It requires an explicit branch allowlist, allowed UTC window, failure thresholds and disabled require_approval. Git projects require a recorded local build of the pinned upstream SHA; remote artifact projects require signatures and comparable versions. For stronger independent approval or a hostile multi-tenant environment, use separate managers/VMs and an external signed approval system; this release does not implement multi-person approval tickets or container/VM isolation.

Build/deploy users are separate, but all builds share one worker identity and all projects share the deployment identity. Project directories prevent accidental cross-project operations, not malicious code with the same Unix identity. Caches under the worker home are shared. Treat source projects as mutually trusted or isolate them with separate OS instances. Private signing keys should remain off production. Service stdout may contain application-generated secrets unknown to the manager; avoid emitting them at source and provision secret values through profiles when redaction is necessary.
